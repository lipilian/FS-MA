02 · Module responsibilities

The executable selects inputs and orders the work. The reusable library owns stereo processing and inference; the plugin provides the custom TensorRT operation.

Application entry points

app/

TSFS.cpp parses a capture directory and optional --measure, loads the engine, and calls rectification, inference, and fused full-image XYZ reconstruction in sequence. The reconstruction method waits for GPU completion before returning. It also reports failures and returns the process exit status.

desktop_main.cpp creates the Qt application and starts DesktopController, which starts calibration and opens an inference-loading splash after successful completion or explicit saved-calibration reuse; reconstruction opens only after FS initialization succeeds. Ordinary calibration close exits.

build_single_engine.cpp is a separate tool: it registers the GWC plugin, parses ONNX, and builds a serialized TensorRT engine.

Shared utilities

core/ · Logger

fs/core/Logger.hpp

Provides Logger::log() and Logger::error() for diagnostic output. The CLI and stereo module use it to report progress and errors.

This folder currently contains logging only. Camera frame/pair types live in capture/IStereoSource.hpp.

Images and camera geometry

stereo/ · StereoFrame

fs/stereo/StereoFrame.hpp

Accepts file paths or in-memory RGB images plus a StereoCalibration. Both constructors share validation and take independent copies of the images and calibration. rectify() runs stereo rectification, builds remap tables, and produces the rectified pair.

StereoCalibration.hpp declares the full raw intrinsics, distortion, rotation, and translation; from_file() reads the existing JSON schema. Callers can also populate these matrices directly. Memory input requires matching RGB CV_8UC3 images and float calibration matrices, with translation in metres.

StereoCameraParameters holds the rectified parameters: fx, fy, cx, cy, and baseline in metres. The class exposes the images and rectified camera parameters.

TensorRT inference

inference/ · FS

fs/inference/FS.hpp

Owns the TensorRT runtime, engine, execution context, CUDA stream, and reusable host/device buffers. Engine loading registers the GWC plugin before deserialization and preallocates the two 960×800 CPU RGB resize images alongside the existing GPU/pinned buffers.

Resizes RGB images to 800 high × 960 wide, packs FP32 NCHW inputs, and submits inference. It scales the rectified camera intrinsics to that grid and retains the baseline.

CUDA postprocessing · Fused XYZ reconstruction

inference/ · PostProcessing

fs/inference/PostProcessing.hpp

fs::postprocessing::compute_xyz_map() fuses disparity validity checks, depth clipping and XYZ projection in one kernel. Each thread handles one pixel; 800×960 uses 3000 blocks of 256 threads with a bounds check and no strided loop. The CUDA source is compiled into fs_core.

The launcher receives read-only disparity, a separate XYZ output, an optional selection mask, dimensions, model-grid intrinsics, baseline in metres, depth limits and the caller's stream. It allocates no buffers and returns asynchronously. Invalid pointers, dimensions, camera parameters or depth limits return cudaErrorInvalidValue.

FS::compute_xyz_map(float min_depth_m = 0.0F, float max_depth_m = 1.0F) uses model_camera_parameters_ and its existing stream. FS allocates and reuses xyz_map_device_: contiguous FP32 [800][960][3], interleaved X,Y,Z in metres (9,216,000 bytes). The original disparity_output_device_ remains unchanged; no extra filtered-disparity or validity-mask buffer is used.

For finite positive disparity d, selected pixels and mandatory u ≥ d, compute Z = fx × baseline / d, X = (u − cx) × Z / fx, Y = (v − cy) × Z / fy. Keep only finite XYZ with Z > 0 and min_depth_m ≤ Z ≤ max_depth_m. Limits must be finite with 0 ≤ min_depth_m < max_depth_m; every rejected pixel writes all three components as zero. Validity is read from Z > 0.

The FS method synchronizes before returning and reports launch and execution errors. Depth limits may be changed and XYZ recomputed without another inference. Call order is the caller's responsibility: load engine, set model camera parameters, prepare images, infer, compute XYZ. No input/inference readiness flags are maintained. FS currently processes the whole image; selection-mask upload, CPU result download and display remain pending.

Independent shared library

inference/plugins/ · GWC

GWCVolumePlugin.hpp/.cpp provide the TensorRT Plugin V3 implementation and registration entry points.

GWCVolumeKernel.hpp/.cu declare and implement the CUDA launcher for groupwise correlation. Both inference and engine building link the resulting libGWCVolumePlugin.so.

Registration includes a C entry point, fs_register_gwc_volume_plugin(), for dynamic loaders.

Camera acquisition · Optional SDK module

capture/ · SentechStereoSource

fs/capture/SentechStereoSource.hpp

Implements IStereoSource with separate workers for left 21LJ548 and right 21LJ530. Device roles match exact names or serials, never enumeration order.

Converts SDK images to owned RGB8 snapshots and returns a StereoCameraPair containing images, frame IDs, camera-local timestamps, and host arrival times. Each pair uses a new frame from both sides, with a configurable host-arrival skew limit.

These are independent continuous streams, not synchronized exposures. CalibrationWorker uses this source for Qt stereo preview and calibration samples. Camera-to-inference UI and raw capture export are planned for the second window.

Experiment and reference code

python/

fs_high_resolution_utils.py contains shared rectification, inference, disparity postprocessing, point-cloud export, constrained mesh construction, and area calculation helpers.

The PyTorch and TensorRT notebooks run experiments and write geometry results; export scripts prepare ONNX models. The C++ CLI does not call this Python pipeline.

The fs:: prefix identifies a C++ namespace (for example, fs::postprocessing and fs::trt); FS:: identifies members of the currently global FS class. C++ build setup

Install OpenCV 4 development files, including aruco (libopencv-contrib-dev on Ubuntu), Qt 6 Widgets (qt6-base-dev), CUDA and TensorRT development files. The recorded development environment uses CUDA 13.3 and TensorRT 11.2; CMake defaults to GPU architecture 120 and requires C++17/CUDA17. The Sentech SDK defaults to /opt/sentech; override it with -DFS_SENTECH_ROOT=/path/to/sdk.

FS_BUILD_DESKTOP defaults to ON. Use -DFS_BUILD_DESKTOP=OFF for file-only builds without Qt or Sentech SDK dependencies. Existing CMake build directories retain their cached option values. VTK is not needed for the current calibration window.

For a fresh build directory on this workstation when CUDA is not on PATH, supply its location explicitly. Pass the compiler location when configuring a fresh directory; existing directories retain their own cached settings:

04 · Runtime flow

This is the actual call order in app/TSFS.cpp. CPU images are prepared first; inference and XYZ reconstruction use the same FS CUDA stream. Reconstruction reads disparity without modifying it and writes a separate XYZ buffer.

  1. Load the engine

    FS::loadEngine() registers the custom plugin, deserializes the engine, creates the execution context, and prepares reusable buffers.

  2. Load the stereo capture

    StereoFrame(left_path, right_path, calibration_path) reads left.png, right.png, and calibration.json.

  3. Rectify the images

    StereoFrame::rectify() performs stereoRectify → initUndistortRectifyMap → remap. Output: rectified RGB images, intrinsics, and baseline.

  4. Prepare the model grid and GPU inputs

    set_model_camera_parameters() scales intrinsics; prepare_stereo_images() resizes, packs, and uploads the pair. Input tensors: [1, 3, 800, 960].

  5. Submit inference or measure ten runs

    inference() calls TensorRT enqueueV3() on the FS CUDA stream. With --measure, inference_time_measure() runs ten inferences, prints GPU timings in milliseconds, and returns their mean.

  6. Compute XYZ inside FS

    compute_xyz_map() reads raw disparity [1,1,800,960] and writes interleaved [800,960,3] XYZ. The CLI uses 0 < Z ≤ 1 m and the mandatory visibility check. It runs once after ordinary inference or the tenth measured inference; reconstruction is excluded from inference timings.

  7. Return after GPU completion

    FS::compute_xyz_map() calls synchronize() internally. Disparity and XYZ remain on the GPU. FS::download_xyz_map() returns an owned, synchronized CV_32FC3 CPU copy; the Qt worker extracts Z for fixed-range Jet display. Denoising and mesh construction are pending.

inference() submits asynchronous GPU work; FS::compute_xyz_map() waits for inference and reconstruction to finish and reports completion errors before returning. FS destruction also waits before releasing its buffers and TensorRT resources. There is currently no public disparity-result accessor. A synchronized result-copy interface is a planned follow-up.

In-memory stereo input · API and ownership

Public headers use the cpp/include root, for example fs/inference/FS.hpp and fs/stereo/StereoFrame.hpp. The file-path constructor loads RGB images and calibration, then delegates to the same validated memory constructor:

#include "fs/stereo/StereoFrame.hpp"

// left_rgb and right_rgb are matching CV_8UC3 RGB images.
StereoCalibration calibration = StereoCalibration::from_file("calibration.json");
StereoFrame frame(left_rgb, right_rgb, calibration);
frame.rectify();

// Use frame.rectified_left(), frame.rectified_right(),
// and frame.rectified_camera_parameters() for inference.

Fully in-memory callers can populate the six StereoCalibration fields directly: left_camera_matrix, right_camera_matrix, left_distortion, right_distortion, right_to_left_rotation and right_to_left_translation.

  • Images must be non-empty, equal-size 2D RGB CV_8UC3. Non-contiguous ROIs are supported. Convert BGR sources to RGB first; the Sentech source already provides RGB.
  • Matrices must be finite, single-channel CV_32F or CV_64F. Intrinsics are 3×3 with positive focal lengths and last row [0, 0, 1]. Distortion is a row/column vector containing 4, 5, 8, 12 or 14 coefficients; use explicit zeros for no distortion.
  • Rotation must be a proper 3×3 rotation. Translation is a nonzero three-element row/column vector in metres. Calibration must match the input image grid.
  • Legacy right_to_left_* field names are preserved. The calibration solver stores OpenCV’s left-to-right transform; these values pass unchanged to stereoRectify, without inversion or unit conversion.
  • StereoFrame deep-copies both images and every matrix, storing calibration as CV_64F. Callers may reuse or release their buffers after construction. Invalid input throws std::invalid_argument; missing or unreadable calibration files also raise exceptions. from_file() reads the required matrices; the frame constructor validates their shapes and values.

Sentech source settings and SDK behaviour

The current implementation is cpp/src/capture/SentechStereoSource.cpp, with pairing and identity helpers in StereoCaptureSupport.hpp. The Qt window binds left STC-MCS500U3V(21LJ548) and right STC-MCS500U3V(21LJ530). The source API also accepts exact user-defined names or serials; missing, ambiguous or same-camera matches fail.

Requested timed exposure defaults to 100,000 µs (100 ms) and is adjusted to the camera’s supported increments. Edit it before connecting; the input is disabled while connected. Continuous automatic white balance is requested when supported. Each camera has its own acquisition worker and produces owned RGB8 snapshots; camera settings are not saved to device user sets.

SentechStereoOptions::max_arrival_skew defaults to 100 ms. Host arrival includes transport latency, while device timestamps belong to independent camera clocks. Keep the board still during capture. Capture errors propagate to the Qt worker, and acquisition threads join before SDK buffers/devices are released.

The library links StApi TL/IP, GenICam, the SDK’s turbojpeg and OpenCV core. It supplies SDK runtime search paths and sets GENICAM_GENTL64_PATH only when absent.

07 · Qt 6 calibration window

Algorithms · fs_calibration

calibration/CharucoCalibration.hpp/.cpp contains RGB ChArUco detection, per-camera and stereo solving, independent reprojection checks, metadata JSON and deep-copy session handoff. It uses OpenCV aruco and existing stereo validation without depending on Qt.

Default board: 10×8 squares, 66.5 mm square side, 50.5 mm marker side, DICT_4X4_250. Internal lengths are in metres.

Desktop · fs_calibration_ui / fs_gui

app/desktop_main.cpp starts DesktopController. CalibrationWindow displays settings, stereo images, sample history and quality. CalibrationController owns the worker thread; CalibrationWorker owns the camera source and performs detection, capture, solve, check and save. widgets/StereoImageView displays owned QImage snapshots.

DesktopController maximizes each main window once after its native QWindow is exposed. The temporary event filter removes itself after scheduling the request; later manual restore/resize operations are preserved. Actual GNOME/X11 checks confirmed both maximization flags and frame geometry matching the screen work area.

Calibration quality uses the fixed fs::calibration::kQualityThresholdPx = 1.0. The worker publishes optional solve/check metrics; the window colors each RMS value green for ≤1.0 px and red for >1.0 px. Missing results/checks have no colored numeric value. The editable threshold control and worker setter are removed; the Finish gate checks only solve stereo RMS. The independent check is optional and its result remains diagnostic.

CalibrationWindow::refreshActions() blocks history-list signals and restores the current row while enabling/disabling controls. This prevents automatic Qt focus transfers from submitting historical-sample previews during Capture; explicit user selection still reaches the worker.

New calibration requires a saved result, matching connected cameras/grid and solve stereo RMS ≤ 1.0 px. A fresh independent check is optional. Startup reads temporary path history from /tmp/FS_Engine-<uid>/fs_gui.conf, tries the last successfully loaded/saved file, then searches the working directory and executable directory for sentech_stereo_calibration.json and calibration.json. A valid loaded file enables Skip calibration · Continue to explicitly reuse it without a fresh check. At either completion boundary the worker stops polling and transfers the current camera source with the confirmed calibration. DesktopController waits for the calibration thread to finish, shows InferenceSplashWindow, and closes calibration. The splash remains visible while the pipeline worker creates FS, loads its engine/context and allocates buffers; ReconstructionWindow is only created on success. Ordinary close cancels the session and exits.

The Qt loader requires board, camera identity and image-size metadata and checks the applied board and fixed camera identities. While connected, reuse also waits for a matching image size. Legacy six-matrix JSON files remain supported by the CLI loader. Confirmed results use fs::calibration::SessionResult, deep-copied into ConfirmedCalibration for handoff; the active source is handed off via SharedStereoSource. Only one worker accesses the source at a time.

08 · Qt reconstruction workspace

Window and worker boundaries

InferenceSplashWindow displays initialization status, elapsed time and cancellation. On failure it offers engine-file selection and retry. PipelineController::initialize() starts worker initialization and emits its completion only after caching the final state and clearing busy status. The reconstruction constructor requires that ready state, so it cannot open with an uninitialized FS. A failed or cancelled load never opens the workspace.

ReconstructionWindow owns collapsible input/calibration details and depth controls, stereo, region, depth and 3D tabs, measurement placeholders and logs. PipelineController serializes actions on a dedicated QThread and provides an atomic cancellation flag. PipelineWorker owns the camera source, frozen StereoFrame and the FS instance initialized during the splash; it invokes the existing core APIs and emits independently owned QImage snapshots.

Stopping takes effect at safe CPU/GPU stage boundaries. Closing waits for worker cleanup, including camera stop and FS destruction, before exiting. No new command-line option bypasses calibration.

Input and calibration ownership

Capture-directory import reads left.png, right.png and, by default, calibration.json. Legacy matrix-only captures follow the CLI path and are labelled as lacking verified grid/camera identity. Available image-size metadata is enforced. The explicit confirmed-calibration option uses the handed-off matrices in memory and requires matching dimensions.

The input/calibration sidebar card starts collapsed and retains its choices across folds and state updates. Camera-session and engine-information sidebar cards are removed; model initialization still happens in the splash. Calibration completion transfers the requested exposure with the source and calibration, and PipelineWorker retains that exposure for reconnects. No additional calibration JSON field is needed.

Live capture always uses the first window’s confirmed calibration. The Rectified checkbox also controls live preview: the pipeline worker caches full-resolution rectification maps and remaps each pair before downscaling, or sends raw RGB when unchecked. Preview signals carry their mode so the window discards queued frames from the previous selection; horizontal guides work on live rectified images. Preview does not replace the frozen input. A fresh capture freezes the raw pair and rectifies it; errors retain the previous valid input. Reconnection binds the confirmed left/right serials.

Polygon editor

widgets/MaskEditor stores one simple polygon in full-resolution rectified-left pixel coordinates. It maps through an aspect-preserving display rectangle, supports click-to-add, close, undo, cancel and vertex dragging, and rejects self-intersections or degenerate regions. Resizing preserves vertices; a new input clears them.

Export produces a binary grayscale PNG at rectified-left resolution using QSaveFile. GPU mask upload, nearest-neighbour inference-grid conversion and geometry updates are still pending.

Available computation and reserved stages

Background execution currently reaches StereoFrame rectification → FS input preparation/inference → compute_xyz_map with configurable metre depth limits. The worker then downloads XYZ and emits owned 960 × 800 rectified-left and Jet depth QImages. The depth tab uses the run’s preset metric range, marks invalid pixels black and clears old results on rerun or new input. The engine, context, GPU I/O/XYZ, pinned host staging and model-size CPU RGB buffers are ready before reconstruction opens. Actual input preparation and camera parameters still depend on the chosen images; reconstruction reuses the existing FS and never reloads the engine.

Raw disparity CPU download remains pending. VTK point cloud/mesh/wireframe, neighbourhood filtering, surface area, SAM prompts and PLY/report/result-bundle export have visible pending areas. Point/triangle counts and area display dashes until their backend exists.

Diagnostics verified preallocated GPU/pinned/CPU buffers, first-input address reuse, and two inferences after deleting only the temporary engine symlink. Initialization occurred once and the replay source was retained.
