02 · Module responsibilities

The executable selects inputs and orders the work. The reusable library owns stereo processing and inference; the plugin provides the custom TensorRT operation.

Application entry points

app/

TSFS.cpp parses a capture directory and optional --measure, loads the engine, and calls rectification, inference, and full-image disparity filtering in sequence. The filter method waits for GPU completion before returning. It also reports failures and returns the process exit status.

desktop_main.cpp creates the Qt application and starts DesktopController, which currently runs the calibration window and exits after completion or cancellation.

build_single_engine.cpp is a separate tool: it registers the GWC plugin, parses ONNX, and builds a serialized TensorRT engine.

Shared utilities

core/ · Logger

fs/core/Logger.hpp

Provides Logger::log() and Logger::error() for diagnostic output. The CLI and stereo module use it to report progress and errors.

This folder currently contains logging only. Camera frame/pair types live in capture/IStereoSource.hpp.

Images and camera geometry

stereo/ · StereoFrame

fs/stereo/StereoFrame.hpp

Accepts file paths or in-memory RGB images plus a StereoCalibration. Both constructors share validation and take independent copies of the images and calibration. rectify() runs stereo rectification, builds remap tables, and produces the rectified pair.

StereoCalibration.hpp declares the full raw intrinsics, distortion, rotation, and translation; from_file() reads the existing JSON schema. Callers can also populate these matrices directly. Memory input requires matching RGB CV_8UC3 images and float calibration matrices, with translation in metres.

StereoCameraParameters holds the rectified parameters: fx, fy, cx, cy, and baseline in metres. The class exposes the images and rectified camera parameters.

TensorRT inference

inference/ · FS

fs/inference/FS.hpp

Owns the TensorRT runtime, engine, execution context, CUDA stream, and reusable host/device buffers. Engine loading registers the GWC plugin before deserialization.

Resizes RGB images to 800 high × 960 wide, packs FP32 NCHW inputs, and submits inference. It scales the rectified camera intrinsics to that grid and retains the baseline.

CUDA postprocessing · Validity filter

inference/ · PostProcessing

fs/inference/PostProcessing.hpp

PostProcessing.hpp declares fs::postprocessing::filter_disparity(); PostProcessing.cu implements the filtering kernel and asynchronous launcher. Each thread processes one pixel; the fixed 800×960 grid uses 3000 blocks of 256 threads, with a bounds check and no strided loop. The CUDA source is compiled into fs_core.

The interface accepts a mutable device pointer for disparity and an optional selection mask, image dimensions, the remove_invisible flag, and a caller-owned cudaStream_t. It does not allocate buffers or create, synchronize, or destroy the stream.

FS::filter_disparity(bool remove_invisible = true) supplies its stream and filters directly in its existing disparity_output_device_ buffer, without allocating another disparity buffer. It currently passes a null selection mask to process the whole image. Filtering follows inference on that same stream; the FS method calls synchronize() internally and checks completion before returning. The low-level CUDA launcher remains asynchronous. Selection-mask upload and CPU result download are still pending. Separate filtering, depth/XYZ, and neighbourhood-denoising kernels can share this CUDA file while retaining intermediate outputs.

Current status: the kernel preserves finite positive disparities selected by the optional mask, additionally requiring u ≥ disparity when remove_invisible is enabled. Invalid values become zero. Validity is determined by disparity > 0; no validity-mask output is allocated or written. The launcher rejects missing required pointers or nonpositive dimensions or a pixel count exceeding INT_MAX with cudaErrorInvalidValue and otherwise returns the CUDA launch status. Completion errors must be checked by the caller. Both FS and the CLI now call the filter. Filtering overwrites the raw disparity. Repeating a filter can remove additional values but cannot recover zeros; rerun inference before relaxing the criteria. The caller must follow loadEngine → prepare_stereo_images → inference → filter_disparity and prepare/infer again after changing inputs or replacing the engine. FS does not track input-preparation or disparity-readiness flags; CUDA error and resource checks remain. The instance must be used serially by its caller.

Independent shared library

inference/plugins/ · GWC

GWCVolumePlugin.hpp/.cpp provide the TensorRT Plugin V3 implementation and registration entry points.

GWCVolumeKernel.hpp/.cu declare and implement the CUDA launcher for groupwise correlation. Both inference and engine building link the resulting libGWCVolumePlugin.so.

Registration includes a C entry point, fs_register_gwc_volume_plugin(), for dynamic loaders.

Camera acquisition · Optional SDK module

capture/ · SentechStereoSource

fs/capture/SentechStereoSource.hpp

Implements IStereoSource with separate workers for left 21LJ530 and right 21LJ548. Device roles match exact names or serials, never enumeration order.

Converts SDK images to owned RGB8 snapshots and returns a StereoCameraPair containing images, frame IDs, camera-local timestamps, and host arrival times. Each pair uses a new frame from both sides, with a configurable host-arrival skew limit.

These are independent continuous streams, not synchronized exposures. CalibrationWorker uses this source for Qt stereo preview and calibration samples. Camera-to-inference UI and raw capture export are planned for the second window.

Experiment and reference code

python/

fs_high_resolution_utils.py contains shared rectification, inference, disparity postprocessing, point-cloud export, constrained mesh construction, and area calculation helpers.

The PyTorch and TensorRT notebooks run experiments and write geometry results; export scripts prepare ONNX models. The C++ CLI does not call this Python pipeline.

The core targets are defined in cpp/CMakeLists.txt. With FS_BUILD_DESKTOP=ON, it also includes cpp/cmake/Sentech.cmake for capture and cpp/cmake/Desktop.cmake for calibration and Qt targets. The core library lets another application reuse the processing code.

fs_core publishes the cpp/include include root and OpenCV/CUDA requirements used by its headers. TensorRT headers stay private; its classes are forward-declared in FS.hpp. Private link dependencies of this static library still participate in the final executable link.

fs_core is a CMake target name, producing libfs_core.a. It is not a C++ namespace or class. The fs:: prefix identifies a C++ namespace (for example, fs::postprocessing and fs::trt); FS:: identifies members of the currently global FS class. C++ build setup

Install OpenCV 4 development files, including aruco (libopencv-contrib-dev on Ubuntu), Qt 6 Widgets (qt6-base-dev), CUDA and TensorRT development files. The recorded development environment uses CUDA 13.3 and TensorRT 11.2; CMake defaults to GPU architecture 120 and requires C++17/CUDA17. The Sentech SDK defaults to /opt/sentech; override it with -DFS_SENTECH_ROOT=/path/to/sdk.

FS_BUILD_DESKTOP defaults to ON. Use -DFS_BUILD_DESKTOP=OFF for file-only builds without Qt or Sentech SDK dependencies. Existing CMake build directories retain their cached option values. VTK is not needed for the current calibration window.

For a fresh build directory on this workstation when CUDA is not on PATH, supply its location explicitly. Pass the compiler location when configuring a fresh directory; existing directories retain their own cached settings:

cmake -S cpp -B cpp/build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_COMPILER=/usr/local/cuda-13.3/bin/nvcc \
  -DCUDAToolkit_ROOT=/usr/local/cuda-13.3 \
  -DCMAKE_CUDA_ARCHITECTURES=120
cmake --build cpp/build --parallel

In VS Code, Ctrl+Shift+B runs the default Build TSFS task. The task builds all enabled targets; despite its name it also builds the GUI when FS_BUILD_DESKTOP=ON. The configure tasks do not override a cached desktop option. Use Run FS GUI for calibration, Run TSFS (Volunteer2 lower/0, Release) for sample inference, or Build FoundationStereo Single Engine (800x960) for engine generation. Ctrl+F5 starts the selected launch configuration. The CMake Tools extension also provides configure/build controls.

04 · Runtime flow

This is the actual call order in app/TSFS.cpp. CPU images are prepared first; inference and filtering use the same FS CUDA stream and reuse the same disparity GPU buffer.

  1. Load the engine

    FS::loadEngine() registers the custom plugin, deserializes the engine, creates the execution context, and prepares reusable buffers.

  2. Load the stereo capture

    StereoFrame(left_path, right_path, calibration_path) reads left.png, right.png, and calibration.json.

  3. Rectify the images

    StereoFrame::rectify() performs stereoRectify → initUndistortRectifyMap → remap. Output: rectified RGB images, intrinsics, and baseline.

  4. Prepare the model grid and GPU inputs

    set_model_camera_parameters() scales intrinsics; prepare_stereo_images() resizes, packs, and uploads the pair. Input tensors: [1, 3, 800, 960].

  5. Submit inference or measure ten runs

    inference() calls TensorRT enqueueV3() on the FS CUDA stream. With --measure, inference_time_measure() runs ten inferences, prints GPU timings in milliseconds, and returns their mean.

  6. Filter disparity inside FS

    Raw output tensor: [1, 1, 800, 960]. filter_disparity() queues full-image filtering in place in the existing FP32 inference output buffer owned by FS. The CLI filters once after ordinary inference or after the tenth measured inference; filtering is excluded from the inference timings.

  7. Return after GPU completion

    Inside FS::filter_disparity(), synchronize() waits for the FS stream and reports asynchronous errors. The CLI needs no separate synchronization call. Filtered disparity remains on the GPU; raw disparity is overwritten; export, display, and depth/geometry construction are not yet implemented.

inference() submits asynchronous GPU work; FS::filter_disparity() waits for inference and filtering to finish and reports completion errors before returning. FS destruction also waits before releasing its buffers and TensorRT resources. There is currently no public disparity-result accessor. A synchronized result-copy interface is a planned follow-up.

In-memory stereo input · API and ownership

Public headers use the cpp/include root, for example fs/inference/FS.hpp and fs/stereo/StereoFrame.hpp. The file-path constructor loads RGB images and calibration, then delegates to the same validated memory constructor:

#include "fs/stereo/StereoFrame.hpp"

// left_rgb and right_rgb are matching CV_8UC3 RGB images.
StereoCalibration calibration = StereoCalibration::from_file("calibration.json");
StereoFrame frame(left_rgb, right_rgb, calibration);
frame.rectify();

// Use frame.rectified_left(), frame.rectified_right(),
// and frame.rectified_camera_parameters() for inference.

Fully in-memory callers can populate the six StereoCalibration fields directly: left_camera_matrix, right_camera_matrix, left_distortion, right_distortion, right_to_left_rotation and right_to_left_translation.

  • Images must be non-empty, equal-size 2D RGB CV_8UC3. Non-contiguous ROIs are supported. Convert BGR sources to RGB first; the Sentech source already provides RGB.
  • Matrices must be finite, single-channel CV_32F or CV_64F. Intrinsics are 3×3 with positive focal lengths and last row [0, 0, 1]. Distortion is a row/column vector containing 4, 5, 8, 12 or 14 coefficients; use explicit zeros for no distortion.
  • Rotation must be a proper 3×3 rotation. Translation is a nonzero three-element row/column vector in metres. Calibration must match the input image grid.
  • Legacy right_to_left_* field names are preserved. The calibration solver stores OpenCV’s left-to-right transform; these values pass unchanged to stereoRectify, without inversion or unit conversion.
  • StereoFrame deep-copies both images and every matrix, storing calibration as CV_64F. Callers may reuse or release their buffers after construction. Invalid input throws std::invalid_argument; missing or unreadable calibration files also raise exceptions. from_file() reads the required matrices; the frame constructor validates their shapes and values.

05 · Current boundaries and next steps

Implemented and verified

Core-library extraction, module-directory migration, and in-memory stereo input are complete. Historical validation recorded in TODO/TODO.md includes Release builds of all targets, normal CLI inference, and ten-run timing on data/Volunteer2_lower/0.

Earlier input checks covered file/memory equivalence, buffer ownership, and invalid calibration. The test sources and targets have since been removed. One initial real-capture comparison failed; five consecutive diagnostic reruns passed. The observation remains recorded in TODO/TODO.md.

Geometry and area computation already exist in the Python reference workflow. The C++ runtime now runs full-image validity filtering after disparity inference. The PostProcessing filter has passed a Release build of fs_core and TSFS with FS_BUILD_DESKTOP=OFF, plus 17 synthetic GPU cases compared exactly against a CPU reference. These cover invalid values, optional masks, visibility boundaries, odd dimensions, the model grid, larger image dimensions, invalid arguments, unchanged selection masks, and non-default stream ordering. The kernel updates the disparity input in place. Real capture data/Volunteer2_lower/0 also passed normal and --measure CLI runs with filtering. Temporary FS diagnostics matched the CPU reference exactly (717783/768000 retained pixels with visibility filtering), verified in-place CPU agreement, reuse of the original disparity buffer, and recovery of removed values by rerunning inference. Earlier integration diagnostics also verified engine reload and destruction with queued work. Earlier diagnostics also checked readiness flags, which have since been removed; call order is now the caller’s responsibility. These checks add no repository test targets. CPU download and display remain pending.

Planned extensions

Stage 1 now includes valid-disparity filtering, depth/XYZ maps, and CLI comparison against the Python reference. The filtering kernel is implemented. FS and CLI integration is complete for full-image filtering. Next are synchronized CPU result access and display; the FS selection-mask upload interface is also pending. Neighbourhood denoising, mesh construction, and area calculation follow later.

Sentech capture has been verified on the real pair at 2448×2048. Camera-rig calibration validation, exposure synchronization, C++ geometry/pipeline modules, and the second Qt/VTK reconstruction window remain pending. The first Qt 6 calibration window is implemented; real-board accuracy validation is still needed.

06 · Connect the Sentech pair

cmake -S cpp -B cpp/build -DCMAKE_BUILD_TYPE=Release -DFS_BUILD_DESKTOP=ON
cmake --build cpp/build --target fs_gui --parallel
./cpp/build/fs_gui

Click Connect cameras in the Qt calibration window. The SDK defaults to /opt/sentech. The desktop target enables the camera source by default; set -DFS_BUILD_DESKTOP=OFF for file-only builds without Qt or the SDK. The standalone OpenCV preview/capture CLI has been removed.

Sentech source settings and SDK behaviour

The current implementation is cpp/src/capture/SentechStereoSource.cpp, with pairing and identity helpers in StereoCaptureSupport.hpp. The Qt window binds left STC-MCS500U3V(21LJ530) and right STC-MCS500U3V(21LJ548). The source API also accepts exact user-defined names or serials; missing, ambiguous or same-camera matches fail.

Requested timed exposure defaults to 100,000 µs (100 ms) and is adjusted to the camera’s supported increments. Edit it before connecting; the input is disabled while connected. Continuous automatic white balance is requested when supported. Each camera has its own acquisition worker and produces owned RGB8 snapshots; camera settings are not saved to device user sets.

SentechStereoOptions::max_arrival_skew defaults to 100 ms. Host arrival includes transport latency, while device timestamps belong to independent camera clocks. Keep the board still during capture. Capture errors propagate to the Qt worker, and acquisition threads join before SDK buffers/devices are released.

The library links StApi TL/IP, GenICam, the SDK’s turbojpeg and OpenCV core. It supplies SDK runtime search paths and sets GENICAM_GENTL64_PATH only when absent.

07 · Qt 6 calibration window

Algorithms · fs_calibration

calibration/CharucoCalibration.hpp/.cpp contains RGB ChArUco detection, per-camera and stereo solving, independent reprojection checks, metadata JSON and deep-copy session handoff. It uses OpenCV aruco and existing stereo validation without depending on Qt.

Default board: 10×8 squares, 66.5 mm square side, 50.5 mm marker side, DICT_4X4_250. Internal lengths are in metres.

Desktop · fs_calibration_ui / fs_gui

app/desktop_main.cpp starts DesktopController. CalibrationWindow displays settings, stereo images, sample history and quality. CalibrationController owns the worker thread; CalibrationWorker owns the camera source and performs detection, capture, solve, check and save. widgets/StereoImageView displays owned QImage snapshots.

New calibration requires a saved result, matching cameras/grid and a passing fresh check. Startup reads temporary path history from /tmp/FS_Engine-<uid>/fs_gui.conf, tries the last successfully loaded/saved file, then searches the working directory and executable directory for sentech_stereo_calibration.json and calibration.json. A valid loaded file enables Skip calibration · Continue to explicitly reuse it without a fresh check. The application releases cameras, stops the worker, displays a completion message, and exits at either completion boundary; the reconstruction window will be added at that boundary. Ordinary close cancels the session.

The Qt loader requires board, camera identity and image-size metadata and checks the applied board and fixed camera identities. While connected, reuse also waits for a matching image size. Legacy six-matrix JSON files remain supported by the CLI loader. Confirmed results use fs::calibration::SessionResult, deep-copied into ConfirmedCalibration for handoff; a live camera session is not handed to a second window yet.
